## 2. 已冻结的经营策略

首个 90 天作战单元：

> 华东地区 × 大型锻件及重型零部件企业 × 台车炉改造 × 温度均匀性不达标

北极星采用两个指标：

1. 滚动 90 天内，工程预审通过后的技术商机数量；
2. 有依据的技术商机预计金额区间。

“进入工程预审”只是过程指标。报价数量、报价金额、成交数量和成交金额分别展示。未知金额显示“待评估”，不得按零处理或由系统猜测。

## 3. 产品与责任边界

- 数炬客户与商机模块是客户、询盘、技术商机、报价和订单的唯一正式记录来源。
- 官网负责承接需求和保存可追溯来源；增长驾驶舱只读分析，不另建客户台账。
- 销售判断需求是否真实；工程判断是否能够承接；争议由总经理裁决并保留双方原始意见。
- 安全、质量和明显不可交付事项属于工程底线，不得被经营裁决覆盖。

业务流程统一为：

> 官网访问 → 开始填写 → 提交成功 → 销售确认询盘 → 有效询盘 → 工程预审 → 技术商机 → 技术方案 → 正式报价 → 成交或丢单

网站漏斗与销售漏斗分开统计，不能把搜索曝光、访问量和商机阶段拼成一条逐人转化漏斗。

## 4. 开工前 P0 问题

### 4.1 公开事实

- 用户于 2026-08-14 确认：首页“150+在职人数”、售后团队与服务站、8/24 小时响应、第三方标志、合作单位名称和实名案例均为真实事实。
- 本轮保持现有公开内容不变，不删除、不匿名化，也不把这些说法扩大到新的页面或宣传渠道。
- 内部继续补齐事实依据、第三方公开授权和确认记录，避免后续人员误改或把“项目经验”写成“全部验收交付”。

### 4.2 询盘与来源

- 当前访问、表单行为和询盘记录是三套独立证据，不能可靠计算网站到询盘转化。
- 询盘缺少能够贯通来源页面、推广来源、飞书通知和数炬商机的唯一编号。
- 英文项目表单缺少企业邮箱、国家、首选联系方式和选填附件，不能承接图纸、工艺文件和招标资料。
- 数炬生产环境尚无正式客户与商机闭环；开发代码能力不能当成已上线能力。

### 4.3 页面与内容

- 中文和英文台车炉产品页可以复用，现有表单可作为改造起点。
- 中文已有改造大修内容，英文没有对应的完整改造页面。
- 英文联系页没有项目表单，全站也缺少统一的“提交项目工况、上传技术资料、预约工程评审”入口。
- 首批案例必须来自真实项目证据，不能用泛化宣传文案替代验收数据和交付边界。

## 5. 建设批次

### 批次 0：事实口径登记

交付物：

- 可公开事实白名单及用户确认记录；
- 第三方标志和实名案例的内部依据、授权或公开来源归档；
- 售后服务能力与承诺边界归档；
- 一个历史项目纸面回放。

验收：所有公开硬事实都有负责人、确认日期和内部依据；本轮不改变已经确认的公开内容。

### 批次 1：打通唯一询盘证据链

交付物：

- 每次官网提交都有唯一编号；
- 来源页面、推广来源、表单提交、官网询盘、飞书通知和数炬记录能够对账；
- 事件失败可发现、可补偿，不能静默丢失；
- 测试数据与真实经营数据明确隔离。

验收：测试提交到数炬记录匹配率 100%，无丢失、重复或错绑。

### 批次 2：重做项目询盘入口

交付物：

- 全站统一三个动作：提交项目工况、上传技术资料、预约工程评审；
- 两步式表单；
- 技术文件为选填；
- 英文表单补齐企业邮箱、国家、首选联系方式和项目交付国家。

验收：桌面与手机均可完成提交；销售能够仅凭第一步信息判断是否需要继续跟进。

### 批次 3：建设首个 90 天核心页面

交付物：

- 台车炉改造核心解决方案页；
- 2—3 个有证据的真实案例；
- 安装、调试、验收、培训、备件和保修边界；
- 价格影响因素和适用、不适用范围。

验收：目标客户能够据此判断“是否适合、能否交付、需要提供什么、下一步怎么联系”。

### 批次 4：接入增长驾驶舱

交付物：

- 数据是否足以决策；
- 当前 90 天作战卡；
- 技术商机数量与预计金额区间；
- 网站漏斗和销售漏斗；
- 渠道、页面与内容证据；
- 带证据、负责人、截止时间和继续/修改/停止结论的周行动卡。

验收：核心事件成功采集率不低于 95%，官网提交与数炬询盘匹配率 100%，有效询盘来源可识别率不低于 90%，商机阶段和时间记录完整率不低于 95%。

## 6. 放行规则

- 7 天只验证数据链和责任链，不能证明市场有效。
- 90 天样本不足时逐条复盘，不比较转化率，不提出预算增减建议。
- 同一轮同时改动多个页面变量时，禁止做因果结论。
- 未完成事实白名单、历史项目回放和询盘对账前，不进入部署流程。
