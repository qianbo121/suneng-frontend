# 独立站 V1.0 第一至第三批实施审核单

更新日期：2026-08-15

当前状态：跨系统终审的高风险问题已经清零，可以进入用户审核；仍有 `.DO_NOT_DEPLOY`，没有提交、合并或部署，不能直接生产发布。

## 一、这次实际完成了什么

### 1. 公开事实保持不变

- 用户已经确认现有公开说法均属事实，本轮没有改动网站公开文案。
- 已建立可公开事实白名单，后续新增页面仍需按同一口径使用，不能自行扩大解释。

### 2. 官网询盘有了唯一证据链

- 每次成功提交都生成唯一提交编号。
- 官网询盘、表单提交、来源信息、飞书通知和数炬记录可以用同一编号对账。
- 同一页面内网络超时后重复点击不会重复创建同一条询盘；客户修改内容后再次提交，也不会被旧记录静默覆盖。
- 飞书通知改为后台可靠发送，不再让客户等待飞书响应。失败、结果未知和人工补发都有状态及处理记录。
- 数炬按提交编号去重，支持英文客户只留邮箱，也能隔离异常记录而不挡住后续正常询盘。
- 多名销售同时处理同一条询盘时，旧页面不能再静默覆盖同事刚保存的结果；发生冲突会要求刷新核对。
- 官网后台和数炬的客户搜索词均放在请求正文，旧搜索地址由代理本地拦截，不进入故障日志。

### 3. 项目表单改成两步轻量表单

第一步只收销售判断是否值得跟进所需的信息：

- 项目类型；
- 公司、联系人；
- 项目地点或交付国家；
- 简要需求；
- 中文填写电话或邮箱其中一个，英文必须填写邮箱，电话选填。

第二步全部选填：行业、工艺、温度、首选联系方式、如何得知苏能。

表单打开、完成第一步和最终提交分别记录。成功后向客户显示提交编号；手机和桌面均可操作。

## 二、本批明确没有做什么

- 安全的图纸、技术协议和招标文件上传尚未建设。不能用普通附件上传临时代替，避免泄露客户技术资料。
- 数炬中的正式客户、技术商机、报价和成交闭环，以及增长驾驶舱经营页面，不属于本批交付。
- 按本批冻结范围，数炬在主管理账号真正进入询盘页时拉取官网数据，不是无人值守的定时同步。官网原始询盘和飞书即时通知不依赖该动作；如果要求“无人登录也必须及时进入数炬”，下一批需要增加后台定时同步和超时告警。
- 没有提交代码、合并主线、部署生产，也没有向真实飞书群发送本版本测试卡片。

### 终审留下的非阻断项

- 数炬同步状态按秒记录，极端同秒备份场景仍可继续提高精度；完整重扫可以补齐，不会删除官网原始询盘。
- 客户在提交响应丢失后刷新页面再提交，或飞书遇到部分模糊网络错误时，仍可能产生重复询盘或重复卡片；官网提交编号可以用于人工核对，原始询盘不会被覆盖。
- 数炬迁移和修改生产密码尚未共用一把维护锁，正式发布时仍必须保证同一时间只有一个生产运维动作。

## 三、上线边界

这次升级放开英文“仅邮箱”询盘后，官网后台和数炬必须一起保持新版本，只能向前修复，不能把整套系统退回旧版本。旧版本看不懂仅邮箱询盘，可能让线索在操作层不可见。

正式发布顺序必须固定为：

1. 备份并冻结切换点；
2. 先升级数炬，完成数据迁移并确认切换点一致；
3. 再升级官网后台和数据库，确认后台健康；
4. 先让新版询盘代理规则生效，再开放新版官网表单，并在前台健康后刷新代理地址；
5. 提交一条生产验收询盘，对账官网、飞书和数炬后再恢复正常运行。

迁移前门禁任一不满足，都必须在触碰数据库前停止；迁移一旦开始，只允许使用兼容新版继续向前修复。新版开放后若要止损，只先退前台、停止新增仅邮箱询盘，后台和数炬继续使用兼容新版并向前修复。
