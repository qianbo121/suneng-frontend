# 苏能官网 GEO 策略（最终执行版 v3.1）

日期：2026-07-29
版本说明：v3 = 对方版执行骨架（P0–P6）+ 我方数据层（55 问实测/渠道地图/已有资产）+ 双方互相验证后的纠偏。取代 v1/v2。
v3.1 修订（四处，均经实测复核）：①基线口径锁定三平台核心面板（3/141），官网 52 次引用拆出品牌 49/非品牌 3；②外发稿降级为"脱敏草稿，精确参数待逐项审核"；③删除"设备参数直接灌入"，改为事实台账"可发布"门槛；④"一词一页"改为"一类采购意图一页"。**核心原则：数据存在 ≠ 数据获准公开。**
范围：仅官网（jssngyl.cn），与智能工厂严格隔离。

---

## 一、总目标

让 AI 在回答工业炉采购/改造问题时：**能抓到苏能 → 能理解苏能 → 相信苏能的数据 → 愿意点名引用苏能 → 最终带来携带真实工件参数的询盘。**

最终战略只有一条：用苏能真实合同、图纸、参数、曲线和验收结果，生产 **AI 无法自行编造、只能引用苏能的工业炉事实**；再通过技术结构、渠道分发、外部证据和持续监测，把这些事实稳定送进 AI 答案。

## 二、指标体系

### 四层指标

| 层级 | 指标 | 说明 |
|---|---|---|
| 抓取 | AI 爬虫**核心页覆盖率** | 不看总次数——爬虫刷首页 100 次不如把核心页各抓一遍 |
| 提及 | AI 品牌提及率 | 55 问固定复测，**品牌词/非品牌词两条曲线，永不合并汇报** |
| 引用 | 官网引用率 | 提到苏能时引用了官网哪个页面、引用内容是否准确 |
| 商业 | **AI 有效询盘数（北极星）** | 见下方定义 |

### 有效询盘定义

至少携带以下 8 项中的 3 项：工件名称/材质、工件尺寸/重量、装炉量/产能、最高温度、热处理工艺、新建还是改造、能源类型、交付地点。

### 复测评分口径（每问每平台）

0 = 未提到苏能 ｜ 1 = 提到 ｜ 2 = 列为候选 ｜ 3 = 引用官网 ｜ 4 = 引用苏能具体参数或案例

### 当前基线（2026-07 实测，GEO 1.0 表）

**核心基线锁定三个完整平台（豆包/DeepSeek/元宝，55 问 × 3 = 165 答）**，通义、Kimi 后续各建独立基线，**不与第一轮合并分母**（否则补测时分母变化会制造虚假涨跌）：

- **品牌词 24/24 = 100%** → 已打穿，守住
- **非品牌词 3/141 ≈ 2.13%** → 主战场
- 官网被引 52 次居全场第一，但拆开看：**品牌词 49 次 / 非品牌词仅 3 次、只覆盖 2 个问题**（江苏工业炉节能改造厂家、热处理炉改造案例）

结论：**品牌实体信任已建立；非品牌主题权威、内容覆盖和外部佐证仍然不足。** AI 认识苏能，但只在被问到苏能时才引用苏能。

## 四、红线（合并版，全程有效，违反即打回）

1. **不编造**任何荣誉、客户、参数、历史、证书；**没有原始证据的数字不进官网**（含存量——青山案例数字同样要过审）。
2. 不做假更新时间；只发布真实发布/修改日期。
3. 不批量生成通用 AI 文章；不为字数堆行业常识。
4. 不做城市名替换的重复页（region-evidence-matrix 六条门槛照执行）；不堆关键词。
5. 不把"爬虫来过"汇报成"AI 已引用"；AI 引流报告只能叫"**可识别 AI 引流**"，不冒充全部；品牌词/非品牌词提及率不合并。
6. 不以文章数、收录量、播放量作为最终成绩。
7. 不买垃圾外链；sameAs 只挂自己能控制或权威确认的页面。
8. 不单独建"AI 专用网站"。
9. 未经技术审核人签字的参数内容不发布。
10. **部署红线**：只提交本次明确文件、不全量覆盖、nginx 先 `-t`、官网+后台+新闻接口+智能工厂域名/容器/路由全验、留可回滚版本、上线后查 200/301/404/日志写入/容器重启次数。GEO 改动与 nginx 日志、智能工厂路由**拆分提交、拆分部署、拆分验收**。
11. 日志隐私边界：不记录正文、表单内容和完整查询参数。
12. 文档/头条等外发内容严守脱敏规则：客户名、报价、完整图纸永不外发。

### P0 收口上线（第 1 周，最高优先级——完成前不新增任何页面）

**P0-0 白名单审计（不从"直接提交"开始）**：①生成当前工作树全量文件清单 → ②标记哪些属于本次 SEO 真实性修复 → ③排除 trace 废件、视觉回归、其他无关修改 → ④确认本地修复测试结果 → ⑤形成精确提交白名单 → ⑥按白名单分批提交部署 → ⑦官网与智能工厂分别验收。**任何未经白名单审计的全量修改不得部署。**

然后组一个独立的"SEO 真实性修复"版本，只含：

- 两篇文章 Article JSON-LD + 真实日期
- sitemap 真实 lastmod
- About 重复内容清理、真实联系方式
- **首页 RSC 数据污染处理**（清库 or 断链，Codex 出方案 → Claude 审 → 再动）
- canonical / hreflang / robots / sitemap 复查，核心页全 200

必须排除：trace 废件三处、视觉回归改动、智能工厂相关配置（拆分处理）。

**验收**：文章页源码有 Article + 可见日期；线上 sitemap 不再统一当天；**首页源码搜不到旧 Banner/占位 Partner**；结构化数据可解析；官网/后台/新闻接口/智能工厂双域名全正常；nginx 日志继续写入。

### P1 监测从"存在"到"可用"（第 1 周并行）

1. **爬虫覆盖率周表**（先 CSV，不开发仪表盘）：每爬虫 × 唯一页面数 / 产品页 / 文章页 / 案例页 / 最后访问 / 200 率。重点盯 GPTBot、OAI-SearchBot、ClaudeBot、PerplexityBot、Bytespider、Googlebot、Bingbot。
2. **询盘事件先证明能入库**：真实页面点击产生 2xx 入库样本 → 确认后才加 AI 来源字典（referrer 域名表见附录 B）+ 首次落地页 + UTM + 表单"从哪里了解到苏能"自报字段。**顺序不可反。**
3. **55 问测试制度化**（不重建基线——基线已有）：表加"轮次/日期/评分(0–4)"列，修 HYPERLINK 脏格式；核心复测面板 = 豆包/DeepSeek/元宝 + **通义补测**（夸克链路）+ **Kimi 新增**（本轮即其基线）；文心降为扩展组（与 ChatGPT/Perplexity 同组，季度测一次）。每月同题复测：固定问法、新会话、同一人，记录引用页与竞品，截图存档。

### P2 事实库（第 1–2 周，给已有资产升级建档，不从零挖）

台账字段（每条事实）：编号（如 TC-LOAD-001）/ 炉型 / 可引用表述 / 数字与单位 / 适用条件 / **原始出处（合同、图纸、验收报告路径）** / 项目时间 / 客户公开状态 / 可公开范围 / **审核人** / 审核日期 / 使用页面 / 状态。

来源优先级：合同技术附件 → 设备总图 → 炉膛/台车图纸 → 温控曲线 → FAT/SAT 验收 → 能耗测试 → 改造前后记录 → 铭牌/出厂检验/获准照片。
起点：把 `case-assets-dedup` 的 18 资产逐条转成事实台账（大半字段现成）。

**第一批优先审核风险最高的存量数字——青山案例**：3 条 1250mm 线 / 年节能约 7644 万元 / 63.7 元/吨 / 120 万吨/年 / 建设与验收周期 / NOx 达标表述。逐条确认测算依据、公开授权、验收证据；确认不了的降级或撤下。

### P3 五页试点（第 2–4 周，不同时改 19 页）

第一批只做 5 页（分别代表核心产品/报价询盘/改造决策/整线能力/结果证据）：

1. 台车炉产品页
2. 工业炉报价参数文章
3. 老旧热处理炉大修还是换新
4. 连续热处理生产线解决方案
5. 青山节能改造案例（数字过审后）

改法（从"企业介绍"到"采购答案"）：开头 100 字给可独立引用的答案（标"历史交付范围/常见配置"）→ 参数表（范围+影响因素+超范围处理+客户需提供什么+以什么文件为准）→ **适用与不适用条件** → 对比决策规则 → 真实证据（项目数字/曲线/图纸局部/验收记录/照片至少一种）→ 责任信息（作者=公司或内容负责人，**技术审核=真实工程师（reviewedBy Person）**，真实日期，数据来源说明）。

> 示例口径：改前"炉膛尺寸、台车承重需按项目参数确认"→ 改后"根据苏能历史交付项目，台车炉常见炉膛 2×4×1.5～6×12×3 米，台车承重 5～80 吨（数字示意，实际以事实库为准）。超出范围属非标，需单独核算。"法律口径不变，可引用性质变。

**发布门槛（达不到不发"优化版"）**：≥3 个过审事实 + 1 张参数/判断表 + 明确适用边界 + 1 项真实证据 + 技术审核人 + 真实日期 + 正确结构化数据 + 询盘参数清单。

5 页验证有效后，同方法扩展到其余 6 产品页 + 2 方案页 + 1 文章 + 1 服务页（即存量 19 页全覆盖）。

### P4 案例分级（第 3 周起持续，质量优先）

**A 级 = 结果案例**：有前后对比数字 + 测量方法 + 测试条件 + 仪器 + 验收标准 + 数据确认人。青山属此类（数字重审后）。
**B 级 = 项目经验记录**：有真实客户/地域/工件/工艺链/供货边界，无获准公开的结果数字。济宁、河南属此类——**不删、不硬灌数字**：

- **精确设备参数（950℃、6400×300×300mm 等）只有在事实台账状态 = "可发布"，并完成原始资料核验、技术审核人签字、客户公开边界确认后才能上线**——设备参数同样可能属于合同/客户/技术保密信息，"数据存在 ≠ 数据获准公开"
- 未通过审批前，沿用外发稿已批准的降级表达（"中高温连续加热工况、数米级有效加热区"）+ 已授权的实名/工艺链信息（如济宁五创机械、连续加热-淬火-回火-喷淋冷却工艺链）
- 页面明确标注"项目经验记录；性能结果因保密暂不公开"
- 台账审批通过一项，页面升级一项；拿到结果数据后升 A 级

节奏：第一批 2 篇标杆（青山重审 + 一篇 B 级升格），此后每月 1–2 篇，从 case-assets P0 清单取材。案例的目标不是讲故事，是**生产 AI 编不出来的独占事实**。每处数据带"该数据仅适用于该项目工况"注记。

### P5 内容扩建（首月不定量，产量由事实库和 55 问缺口决定）

- 前一个月**不承诺每周页数**；月度复测后，按"AI 不提苏能的问题"排序，每月做 **2–4 个高证据页面**，一个问题彻底打穿再做下一个
- 选题只来自五个源头：55 问缺口 / 销售真实询盘 / 搜索进入词 / 爬虫实际抓取 / 事实库里能公开的独有证据
- 打击顺序（按 55 问分组）：费用与回报（7 词）→ 风险与过程（8 词）→ 技术方案（15 词）→ 厂家选择（8 词）。**42 个失败词先归并为采购意图集群再立项，页数会明显少于 42**（如"电改气/气改电"是一页决策的两个方向，"改造多少钱/预算怎么估/报价包括哪些"是一个费用集群）
- **一类采购意图一页**：近义问题合并为一个集群，一个权威页覆盖一组相同决策需求；只有用户意图、所需证据和解决方案明显不同才拆独立页——否则站内关键词互相竞争、重复内容稀释权重
- 长期地图：炉型词 × 工件/工艺词 × 采购意图词矩阵（新页必须有真实来源、独有数据、决策价值、不重复、能指向产品与案例）
- 二期题库（新炉采购词：台车炉怎么选/多少钱/均匀性验收等）待改造线见效后启用

### P6 渠道分发 + 外部背书（第 2 个月起并行）

**为什么必须做**：爬虫数据证明 AI 蜘蛛基本不深爬官网；引用数据证明 AI 答案大量引用第三方平台——**爬虫不来你家，就把内容送到它常读的地方**（两组实测数据同向）。

渠道作战地图（来自 55 问引用源聚合，附录 E 全表）：

| 渠道 | 直接喂给 | 弹药 |
|---|---|---|
| 文档平台（book118 被引 47 次） | 豆包 | pack 脱敏技术文档 |
| 微信公众号（17 次） | 元宝 | pack 案例改写 |
| 头条号（14 次） | 豆包 | 案例+问答改写 |
| 百度百科（20 次） | 元宝/文心 | 企业+产品词条 |
| 企业信用/招聘平台（合计 87 次） | 全平台品牌词 | **企查查/启信宝/水滴/BOSS/智联的公司简介按官网首页标准维护** |
| 知网（20 次，DeepSeek 主粮） | DeepSeek | 唐工挂名技术文章 1–2 篇（慢，不贪多） |
| 客户新闻/协会/展会/招投标公示 | 全平台 | 随案例授权逐个争取；中标信息本身就是背书 |

外部权威三层优先级：官方可核验（企业信用/知识产权/认证/招投标）→ 行业权威（协会/展会/客户官网/行业媒体）→ 经营平台（1688/慧聪/地图/目录）。所有平台名称、地址、电话、Logo、产品范围一致。
署名结构：作者=公司或内容负责人；**技术审核（reviewedBy）=真实工程师 Person 实体**；发布者=公司。审核人职务与从业年限须本人及公司确认，不许代写"30 年经验"。
sameAs 只挂能控制或权威确认的页面，成一个挂一个。`llms.txt` 优先级最低。
