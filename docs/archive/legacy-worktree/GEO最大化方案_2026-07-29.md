# 苏能官网 GEO 最大化方案 v2.0（真正最大化版）

日期：2026-07-29
版本说明：v1 极限档经对抗复核修正 10 处（其中 3 处为实质错误：Dataset 误用、两周淘汰与收录时延自相矛盾、站外并行先发）。本版为修正后的最大化打法。
**定位不变：v3.1 是正式执行主干。本版供整体采用（需资源到位）或抽模块并回 v3.1。**

---

## 一、最大化公式

> **高价值问题覆盖率 × 可引用事实密度 × 独立外部验证 × 抓取索引效率 × 有效询盘转化**

不是页面数 × 渠道数。AI 最终引用的是一个结论、一张表、一个数字——不是一篇文章。所以最大化的对象是**可引用事实的覆盖率**，不是文案产量。

---

## 二、不砍的底线（最大化版同样生效）

不编造 / 不假日期 / 不城市页不堆词 / 不买垃圾外链 / 未授权信息不外发 / P0-0 白名单部署完整执行不压缩验收。这些是 GEO 的技术要求，砍了直接负分。

结构化数据规范（修正后）：
- 案例/内容页用：Article 或 WebPage + BreadcrumbList + Organization + Product/服务关联 + author + **reviewedBy（真实工程师 Person）** + 真实日期
- **Dataset 只用于真正的数据集**（可下载、有字段说明、版本、许可）——普通参数表不是 Dataset
- FAQ 保留内容价值：只写买家真实会问的，不机械凑 3–5 问，不拿 JSON-LD 数量当质量
- `llms.txt` 最低优先级（对 Google 明确无效果，对国内平台无证据）

更新口径（修正后）：**有新证据才更新正文和 lastmod；没有就保持原日期。** 不设"每页每月必须更新"的 KPI——lastmod 必须反映真实显著更新，否则会被验证机制忽略。

## 三、执行计划

### 第 0 周：授权会战（引擎，不变，加三道状态）

唐工 + 钱波集中 2–3 个整天，18 资产逐条过三道门：

| 门 | 问题 | 签字人 |
|---|---|---|
| ① 技术准确 | 数字和表述对不对 | 唐工 |
| ② 公司允许 | 苏能愿不愿公开 | 钱波 |
| ③ 客户允许 | 客户授权范围内吗 | 客户确认记录 |

三门全过 → "精确值可发布"；缺任一 → "范围表达"或"禁发"。产出全量可发布事实清单。

**客户合作方式（修正：不拿反链当筹码）**：联合项目案例 / 客户官网或公众号项目新闻 / 客户技术负责人共同审核 / 展会协会联合材料 / 授权引用验收结论。独立客户来源对 AI 信任的贡献远高于互挂 Logo 和链接。

### 并行：P0 收口上线（完整执行，不因提速压缩验收）

白名单、trace 排除、双域名验证、可回滚、nginx/容器检查——一步不省。

### 官网发布：滚动三批，不一次全上（修正）

19 个存量页分 **5 / 7 / 7 三批**，每批间隔 3–5 天：
- 每批完成技术验收（结构化数据解析、200、内链、日期）+ 内容验收（质量门）再发下一批
- 不等排名结果，但保留问题定位和回滚能力
- 比一次全上只慢约一周，出问题时能知道是哪批哪类改动引起

### 主题页：8–12 个权威主题，不是 15–20 页（修正）

**页数是聚类的输出，不是目标。** 聚类方法：
1. 42 个失败词 × 它们的引用 URL 建关系表（GEO 1.0 数据现成）
2. 引用来源高度重合的问题合并
3. 用户决策相同的问题合并
4. 只有所需证据和解决方案明显不同才拆页

预计落在 8–12 个主题：改造还是换新 / 节能收益与 ROI / 改造费用与报价边界 / 停产周期与生产影响 / 改造验收指标 / 炉衬·燃烧·余热回收 / PLC·DCS 控制升级 / 老炉重启与再制造 / 改造失败原因 / 改造厂家怎么选。
一个权威页覆盖一组问题，好过三个相似页互相竞争。

### 三个工具（新增模块，胜过多写十篇）

| 工具 | 形态 | 注意 |
|---|---|---|
| 工业炉改造 ROI 计算器 | 交互器给人用；**旁边必须配静态公式说明+示例表**（AI 爬虫不执行 JS，被引用的是这部分） | 每个输出数字来自事实库+挂适用边界，否则成"苏能承诺" |
| FAT/SAT 验收清单 | 可下载 PDF/Excel（均匀性/控温精度/空炉负载/联锁/能耗/排放/资料交付） | 引用真实标准号；这才是配得上 Dataset 标记的候选 |
| 询价参数模板 | 可填写下载，直通询盘表单 | 与现有表单参数清单打通，带来源标记 |

工具有真实使用价值，天然吸外链，也最容易被 AI 当"明确答案"引用。

### 资源配比：80/20（修正）

- **80% 资源打工业炉改造线**（非品牌突破口全在这里：已有 3 次提及都是改造/厂家选择类）
- 20% 维护台车炉、连续线等已有产品页
- 改造线出现**稳定引用**后，新炉采购线才升到 50%。最大化不是全线开战，是先打穿最可能突破的一条线

### 发布与分发顺序（修正：官网永远先发）

1. 官网发布完整原始版本
2. 更新 sitemap + 主动提交（百度站长 / GSC / Bing·IndexNow——收到 200 只代表收到，不代表必收录）
3. 从首页/服务页/产品页建标准 HTML 内链
4. 查 nginx 日志确认开始被抓
5. **48–72 小时后**站外发**摘要或改写版**，标注来源并链接官网原文，保留独立信息价值，不纯复制

### 渠道：首月只跑 4 条（修正）

官网 + 公众号（→元宝）+ 一个文档平台（→豆包）+ 一个权威渠道（企业信用平台对齐或百科）。
头条、B2B、期刊、其余百科按效果逐月加入。没有专职运营之前，8 条同时铺开的结局是断更+复制+口径不一。

### 事实单元制（把"页面生产"升级为"事实生产"）

每个事实单元：唯一编号 / 一句话结论 / 数字与单位 / 适用条件 / **不适用条件** / 原始证据 / 技术审核人 / 版本与审核日期 / 使用页面。
一个事实合法复用到：产品页、案例页、采购指南、公众号、销售资料——最大化的是事实覆盖率，不是文案数量。

## 四、测量：双频率 + 决策门（修正：不做两周淘汰）

**高频哨兵组**：12 个最高价值问题，每两周测，关键问题重复 2–3 次抗模型随机波动——只看方向，不做生死判决。
**完整基准组**：55 问，每月（或每 6 周）固定平台/问法/新会话完整复测，两条曲线照旧。

决策门：
- **D+30**：查抓取、索引、初次引用（技术问题此时修）
- **D+60**：调标题、内链、证据表达
- **D+90**：保留 / 合并 / 重写 / 下线

两周只能修技术错误，**不能因为"还没被 AI 引用"删内容**——收录本来就要 2–8 周。

补充指标：AI 可识别引流 / 有效询盘 / 引用问题覆盖率 / 官网域名引用占比（对第三方平台引用的比值——防止站外分发反客为主）。

## 五、风险账本（v2 更新）

| 风险 | 处理 |
|---|---|
| 竞争暴露（精确参数公开） | 授权会战三道门里由钱波拍板，逐条决定 |
| 客户关系摩擦 | 用联合案例/共同审核替代生硬索取 |
| 第三方压过官网 | 官网先发 + 48–72h 时差 + 站外只发摘要 + 监控官网引用占比 |
| 质量方差 | 滚动三批 + 质量门，不靠事后砍 |
| **唐工带宽（最硬约束）** | 第 0 周 2–3 天 + 每周半天签批；给不出→整体回落 v3.1 |
| 运营人力 | 4 渠道后压力减半，仍需明确责任人 |

**降级开关不变**：授权会战做不了或运营没人接，自动回落 v3.1，不搞半吊子最大化。

## 六、结论

真正最大化版 = **v3.1 主干 + 三个极限模块**：
1. 第 0 周授权会战（三道门，一次解锁 v3.1 全部"有条件/暂缓"）
2. 滚动三批发布（5/7/7，速度接近全量、风险接近试点）
3. 渠道提前试投（首月 4 条，官网先发 + 48–72h 时差）

外加三工具和事实单元制作为增量模块。不整体采用 v1 极限档——它最伤 GEO 的四个点（批量重复、错误结构化数据、第三方压官网、过早淘汰）已在本版全部修掉。
