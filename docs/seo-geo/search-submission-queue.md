# 搜索提交队列

正式发布是服务器上的人工切换，不是候选构建任务完成。队列每天及手动运行时读取**线上**网站地图，与上次保存的快照比较，把新增网址和真实修改时间变化的网址加入待提交队列。未发布的候选不会触发入队。

## 第一次升级

`frontend/scripts/search-live-baseline.json` 是 2026-09-20 读取的 208 个线上网址与原有修改时间，不会修改网站地图。首次仅补入已确认新发布的 8 篇指南；没有整站提交。之后使用队列存档里的快照，不再重建初始基线。老存档没有快照时可平滑升级，旧待提交项保留。

没有修改时间的既有页面仍遵循原策略。修改这些页面后，在实际发布、核对线上内容之后，手动运行 Search Submission Queue 并填写改过的正式网址；不要拿部署日期冒充内容日期。

## 保存与验收

- 待提交项和快照在请求搜索平台之前一起保存。缺少凭证、拒绝、超额或超时都保留未确认项目；下次继续。
- 删除的页面从待提交队列移除。损坏、丢失或过期的存档停止运行，不清空后重建。
- 日志分别报告线上新增/变化数、待提交数和平台接收结果。平台接收不等于搜索收录。
- `node frontend/scripts/search-submission-queue.mjs --state-file=... --batches-file=... --dry-run` 只读取网站地图、计算待提交项，不保存状态、不向搜索平台提交。

## 百度连接失败的处理

用户于 2026-09-22 选择保留安全校验、必要时通过百度后台提交。为落实这一选择，每日队列明确使用 `BAIDU_SUBMISSION_MODE=manual`；脚本未指定该选项时也默认手动模式。

- 百度只保留和更新待处理清单，不自动发送、不新增尝试预算；任务不再注入百度提交密钥。已有密钥没有被删除或重置。
- 新增的真实线上网址仍被发现并保存，其他搜索引擎照常发送，队列存档照常保存。日志明确写“主动暂停、未确认接收”，不能把任务整体成功当成百度接收成功。
- 手动触发整个队列也不会绕过百度暂停；后台只在必要时处理少量重要新页面，不要求把历史队列逐条补完。没有逐网址回执，不凭成功总数批量移出队列。
- 重新启用 `auto` 模式须另行确认安全入口并授权恢复，不在本次选择范围内。本地修改尚未合并到主线前，远程日常任务仍按原配置运行。

2026-09-22 的不带凭证连接检查复现了 `data.zz.baidu.com` 的证书域名不匹配。百度官方说明列出的推送接口仍为明文 HTTP；这不等于已获准把密钥改为明文传输。

- 提交脚本坚持 HTTPS 和证书校验，禁止自动跟随百度提交接口的重定向，也不自动降级到明文连接。
- 传输异常日志只输出固定的错误分类，区分证书、域名解析、超时和连接失败；不输出原始异常、请求地址或密钥。失败保持任务失败状态，未确认的网址继续留在队列，其他搜索引擎独立处理。
- 每日尝试预算是本地防重复措施，不代表百度实际收到或消耗了平台额度。后台某日的成功总数也不能用来猜测哪些具体网址已接收，不能据此批量移出队列。

本项改进只让失败原因可核查，**不代表百度自动提交已经恢复**。恢复须先确认官方支持且证书有效的加密入口；如果只有明文入口，需要用户明确接受密钥传输风险后另行处理。不要关闭证书验证，也不要反复人工补交整个历史队列。

参考：[百度官方接口说明](https://ziyuan.baidu.com/college/articleinfo?id=3019)。

## 网站所有权验证

两个正式构建流程已经接收百度、必应、360、搜狗的公开所有权验证值，可放在仓库同名变量或同名受保护配置中。名称为 `NEXT_PUBLIC_BAIDU_SITE_VERIFICATION`、`NEXT_PUBLIC_BING_SITE_VERIFICATION`、`NEXT_PUBLIC_360_SITE_VERIFICATION`、`NEXT_PUBLIC_SOGOU_SITE_VERIFICATION`。

这些值必须由站长后台提供；不要填占位符。代码接线不代表后台已经验证，已有文件或域名验证也不能仅凭网页缺少标记判定失效。补值后要重新构建候选，实际发布后再核对页面标记与后台状态。

## 发布边界

前端镜像修复新闻/产品错误地址和英文搜索文案；未知 PHP 地址的修复在 `nginx.prod.conf.template`，**仅切换前端镜像不会使这条服务器规则生效**。发布时须单独授权更新对应网站的服务器规则，先做语法检查，保留精确旧地址映射与其他站点配置，再核对未知地址返回真正的不存在状态。
