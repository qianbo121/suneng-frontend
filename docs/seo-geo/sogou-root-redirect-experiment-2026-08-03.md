# 搜狗根路径 308 实验记录

日期：2026-08-03  
范围：只调整 `https://www.jssngyl.cn/` 的根路径响应；不改新闻、正文、内链、sitemap、lastmod，不做主动索引提交。  
目的：验证固定永久跳转能否减少搜狗在 `/` 与 `/zh` 之间的重复访问，并提高正文页面发现效率。

## 一、证据口径

- 数据源：生产持久化 Nginx `www.access.json*` 原始日志。
- 主机范围：`www.jssngyl.cn`。
- 爬虫口径：`crawler_family=sogou_spider`。
- 排除：`monitoring_probe=crawler_verification` 与既有人工验证 request ID。
- 日志可用窗口：北京时间 2026-07-29 00:23:33 至 2026-08-03 23:41:39。
- 快照生成时间：北京时间 2026-08-03 23:42:44。
- URL 去重依据：日志中的标准化请求路径；含首页、正文、旧路径和少量静态资源，因此复测必须沿用同一算法。

## 三、实验改动

- `https://www.jssngyl.cn/` 固定返回 `308`，目标为 `https://www.jssngyl.cn/zh`。
- 不再让根路径依据 `Accept-Language` 在 `/zh` 与 `/en` 之间临时分流。
- `/en` 继续直接返回英文站，页面上的 EN 入口继续保留。
- HTTP 与裸域跳转本轮不改，防止扩大变量范围。

## 四、上线即时验收

- 无请求头、`zh-CN`、`en-US` 和搜索爬虫 UA 请求根路径时，均应得到同一 `308 -> /zh`。
- `/zh` 与 `/en` 均应返回 200。
- sitemap 不应包含重定向源根路径。
- 官网后台、智能工厂、成文子域名、工时二维码兼容跳转均不得受影响。
- 生产 Nginx 模板必须先通过候选配置 `nginx -t`，再替换活动配置并平滑 reload。

## 五、后续复测

D+1、D+3、必要时 D+7 使用同一日志算法，分别比较：

1. 根路径 307 是否归零、308 是否按预期出现；
2. `/` 与 `/zh` 的请求数和占比；
3. 搜狗 2xx 正文请求数；
4. 去重 URL 数；
5. 六个新页面覆盖率；
6. 是否产生新的 404、5xx 或跳转循环。

判定标准不是总请求越多越好，而是首页重复访问占比下降、正文去重覆盖增长。D+3 趋势明确即可冻结结果并进入新闻路由治理；若波动不明确，延长至 D+7。观察期不同时做新闻路由、内链、sitemap、lastmod 或主动索引提交，避免污染归因。

## 六、部署与即时验收记录

- 正式生效时间：北京时间 2026-08-03 23:55:19。
- 部署方式：只更新生产 Nginx 模板和部署保护，候选配置通过 `nginx -t` 后平滑 reload；未重建官网、智能工厂或成文容器。
- 回滚点：生产宿主机保留 `nginx.prod.conf.template.pre-root-308-20260803-2350`，容器内保留 `/tmp/nginx.conf.pre-root-308-active`。
- 首次热更新检查发现：宿主机上的单文件模板被 Git 替换后，运行中容器仍指向旧 inode，因此候选配置虽然语法通过，却没有包含本次 308。该次没有改变活动行为，也没有造成对外中断。随后改为显式把已审计模板复制进容器再渲染，并在部署脚本中固化这一机制。
