## 一、结论

“工业炉改造验收看哪些指标”本轮未出现苏能，不是页面无法访问、未进入 sitemap、canonical 错误或爬虫完全没有抓到造成的。

当前更可信的诊断是：

1. 验收新闻已经具备基础 SEO 可发现性，且有 GPTBot 与 Baiduspider 的真实 200 访问记录；
2. 页面缺少可直接摘取的“验收对象—测试条件—记录证据—判定边界”答案结构，FAT 与现场验收的分界没有形成明确答案；
3. 页面写到 TUS、SAT，但当前语境中的 SAT 是与 TUS 并列的 System Accuracy Test（系统精度校核），不能解释成 Site Acceptance Test（现场验收）；
4. 页面没有可核验的公开标准号，亦没有已授权的报告编号、校准记录或第三方检测示例；后者在证据到位前不得补写；
5. 与该主题相邻的一篇老新闻存在裸 Markdown 标记直接展示的问题，这是已确认的页面质量故障，但不是验收新闻未被引用的唯一原因；
6. R2 的豆包样本没有记录来源网址，因此豆包的“0”只能表示本次记录未观察到，不能证明豆包没有任何来源。

因此，本页应保持冻结至 2026-08-29 完整复测结束。现阶段只归档诊断，不提前改稿，不制造 `lastmod`，不新增无法核验的标准或报告编号。

## 四、内容与结构诊断

### 4.1 已有优势

- 标题直接覆盖“工业炉改造验收看哪些指标”；
- 正文已覆盖安全、升温、保温、温度均匀性、控制、机械、能耗等验收方向；
- 已提示测试条件不能脱离负载、装炉、测点、保温时间等边界；
- Article、BreadcrumbList、LocalBusiness 等基础结构化信息已存在；其中 LocalBusiness 属于 Organization 的子类，页面实体 `@id` 复用 `/#organization`；
- 页面可访问、可索引、有站内入口，并已有真实爬虫访问。

### 4.2 主要缺口

#### 缺口 A：直接答案不够可摘取

页面更像连续说明文，而不是买家可以直接复用的验收清单。当前没有把以下四层绑定成同一张表：

1. 验收对象：安全联锁、温度、机械、产能、能耗、排放；
2. 测试条件：空炉/负载、工件、装炉方式、测点、保温时间、统计周期；
3. 证据文件：测试大纲、仪器校准、原始记录、偏差关闭、双方签字；
4. 判定边界：设计目标、工厂测试、现场验证、正式验收分别能证明什么。

这会降低页面被 AI 直接摘取为“明确答案”的概率，但不是单一因果证明。

#### 缺口 B：FAT 与现场验收边界缺失

验收新闻中 `FAT` 为 0。页面出现一次 `SAT`，原句与 TUS 并列，语境指向 System Accuracy Test，不是 Site Acceptance Test。

因此，页面当前没有回答：

- FAT 在工厂验证什么；
- 现场到货、安装、冷态、热态、负载分别验证什么；
- FAT 为什么不能替代现场验证；
- 各阶段应留下哪些记录。

后续改稿必须避免使用单独的 `SAT` 缩写造成歧义。建议写全称：

- `System Accuracy Test（系统精度校核）`；
- `Site Acceptance Test（现场验收测试）`。

#### 缺口 C：标准与独立证据不足

验收新闻未出现 GB/T、JB/T、YB/T、AMS2750 或 CQI-9 等标准号。公开标准号能够增强可核验性，但不是 AI 引用的必要条件；R2 元宝来源中也存在普通企业自建站文章，因此不能把“没有国标号”定为唯一根因。

标准号、适用版本和适用场景需由唐工或有效标准资料确认。报告编号、校准记录、第三方检测示例必须先有原件与发布授权，不能为增强 GEO 而补造。

#### 缺口 D：FAQ 结构缺失

验收新闻没有 `FAQPage`。如果后续正文确实新增买家真实问题，可同步生成与可见内容一致的 FAQPage；不能只加 JSON-LD、不能为凑数量硬编问题。

#### 缺口 E：品牌与答案的绑定较弱

页面后段才集中介绍江苏苏能工业炉的服务能力。即便未来 AI 摘取前面的验收方法，也可能只拿走方法而不形成品牌归属。

这与“节能改造多少钱”已出现的“引用官网但未记录到苏能”属于同类风险，但验收题当前连官网引用都未观察到，因此品牌绑定不是本页唯一优先项。

### 4.3 已确认的相邻页面故障：裸 Markdown

“老旧热处理炉是大修好，还是直接买新的”新闻正文把 Markdown 符号直接存入 HTML 内容。生产公开接口中可检出：

- 标题标记合计 26 处，其中 `### ` 标记 16 处、纯 `## ` 标记 10 处；
- `* ` 列表标记 65 处；
- `**` 粗体标记 1 对。

线上服务端 HTML 也直接出现“`## 三、老旧热处理炉大修通常改哪些地方？`”。这是面向用户和爬虫都可见的渲染质量问题。

它应单独修复，但该页在 R2 已被元宝记录为引用来源；在 8 月 29 日复测前修复会增加新的实验变量。因此本报告只登记故障，默认等完整复测后处理；若因用户体验决定提前修复，必须作为独立事件写入实验台账。

6. 在直接答案中自然绑定“江苏苏能工业炉有限公司”的工程判断，但不写成无条件承诺；
7. 为非 JavaScript 抓取端保留可见的电话、邮件或标准 `<a>` 联系入口；弹窗继续服务真人转化。
